- That release raises the interactive HTTP service's response write deadline from the thirty-second `github.com/bborbe/http` default to ten minutes

The library change in v0.97.1 (`bborbe/agent` v0.97.0 → v0.97.1, three commits, with no change to its own `go.mod`): `interactive/service.go`'s `Run` now builds its HTTP server as `libhttp.NewServer(s.listen, s.Handler(), serverOptionFns()...)`, where `serverOptionFns()` sets `libhttp.ServerOptions.WriteTimeout = 10 * time.Minute` — previously the server ran on the `github.com/bborbe/http` thirty-second default. Only a variadic options parameter was added to `libhttp.NewServer`. `interactive.NewService` and `interactive.NewServiceWithPermissions` are unchanged, and this repository calls neither `libhttp.NewServer` nor `github.com/bborbe/http` directly — so no Go source change is needed here.

Why the deadline matters: Go sets the write deadline when the request headers are read, so a handler that outlives the deadline reaches a deadline that has already passed and can no longer write its response. The turn completes server-side and the answer is silently lost, surfacing to the caller as `502 Bad Gateway`. Measured against the deployed `claude-interactive` service in nuke dev: 27.9 s returned 200; 32.5 s and above returned 502 on every attempt. This repository publishes that image, so the new library has to land here.
